# x402 Paid API

## What is x402

[x402](https://x402.org) is a machine-payable extension of the HTTP `402 Payment Required` status
code: an unpaid request gets a structured challenge describing exactly how to pay (network, asset,
amount, payout address), the client resubmits with a payment header, and a facilitator service
verifies and settles the payment on-chain before the real handler runs. In this repo it's used to
meter a single paid oracle-ask call without building any billing/account system — payment is
per-request and stateless.

## How POST /api/x402/ask works

`POST /api/x402/ask` is the paid twin of `POST /api/ask` — same request body (`AskBody`), same
underlying `answerOracleAsk` handler — gated by an x402 payment challenge/response flow:

1. Client calls `POST /api/x402/ask` with no payment header.
2. Server responds `402` with payment requirements (network, asset, amount, payout address) instead
   of running the handler. This attempt is logged with status `unpaid`.
3. Client resubmits the same request with a `payment-signature` header carrying a signed payment
   payload.
4. The facilitator (`X402_FACILITATOR_URL`) verifies the payment. If verification fails, the
   attempt is logged `rejected` and a `402` is returned again.
5. If verification succeeds, the `/api/ask` handler runs. If the handler itself fails
   (status >= 400), the payment is cancelled and the attempt is logged `handler_failed`.
6. If the handler succeeds, the payment is settled on-chain via the facilitator. If settlement
   fails, the attempt is logged `settlement_failed`.
7. If settlement succeeds, the attempt is logged `settled` (with `payer`, `transaction`, and the
   settled `amount`), and the ask response is returned to the client as normal.

Every attempt — regardless of outcome — is written to the `x402_request_log` table
(`src/db/x402-schema.ts`) via `logX402Request` (`src/routes/x402/logging.ts`), which never throws
so logging failures can't break the request.

If `X402_PAYOUT_ADDRESS` is unset, `createPaidAskRoutes` returns a no-op Elysia app and the route is
never registered — the server boots normally on deployments that haven't opted into monetization.

## Required environment variables

Set these in `.env` (see `.env.example`):

| Variable | Purpose |
| --- | --- |
| `X402_PAYOUT_ADDRESS` | Your EVM wallet address (`0x...`) that receives payment. Receive-only — no private key needed here. Unset = the paid route doesn't exist. |
| `X402_NETWORK` | Which chain to settle on, as a CAIP-2 id, e.g. `eip155:84532` (Base Sepolia testnet, default) or `eip155:8453` (Base mainnet). |
| `X402_PRICE` | Price per `/api/x402/ask` call, in USD, no `$` prefix (some `.env` loaders expand `$0` as a variable). |
| `X402_FACILITATOR_URL` | The x402 facilitator endpoint that verifies and settles payments, e.g. `https://x402.org/facilitator`. |

## GET /api/x402/stats

Returns aggregate totals plus a page of recent log entries. Supports `limit` (default 50, max 200)
and `offset` query params for paging through `recent`.

```bash
curl -s "$BASE/api/x402/stats?limit=5"
```

```json
{
  "totals": {
    "requests": 42,
    "settled": 30,
    "rejected": 4,
    "unpaid": 6,
    "failed": 2,
    "revenueAtomic": "300000000",
    "revenueApprox": 300.0
  },
  "recent": [
    {
      "id": 42,
      "route": "/api/x402/ask",
      "status": "settled",
      "network": "eip155:84532",
      "asset": "0x036CbD53842c5426634e7929541eC2318f3dCF7e",
      "amount": "10000000",
      "payer": "0xabc123...",
      "transaction": "0xdeadbeef...",
      "errorReason": null,
      "createdAt": 1753900800000
    }
  ]
}
```

Field notes:

- `totals.failed` combines `handler_failed` + `settlement_failed` (both mean payment was attempted
  or completed but the request still didn't succeed).
- `totals.revenueAtomic` is the sum of `amount` across `settled` rows, in the asset's smallest unit
  (a string, since it can exceed safe integer precision).
- `totals.revenueApprox` divides `revenueAtomic` by `10^6`, i.e. it assumes a 6-decimal stablecoin
  (USDC and every asset x402 defaults to today). Treat it as an approximation, not an exact figure,
  if a different-decimal asset is ever used.
- `recent[].status` is one of `unpaid` | `rejected` | `handler_failed` | `settlement_failed` |
  `settled`.
- `recent[].createdAt` is epoch milliseconds (`Date.now()` at log time), not an ISO string.
- `network`, `asset`, `amount`, `payer`, `transaction`, `errorReason` are `null` when not applicable
  to that row's status (e.g. `unpaid` rows have no payer/transaction yet).
