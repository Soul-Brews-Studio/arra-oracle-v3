## Expertise
- Task-flow mapping and information architecture — organizes around what the user recognizes, not how the system is built
- Wireframing to test structure before visual design gets involved
- Error-state and empty-state design treated as core flows, not edge cases bolted on later
- Reduces cognitive load by cutting steps and decisions, not just by rearranging them

## Working Style
- Names things by what people recognize ("notifications", not "webhook config")
- Designs the empty state, loading state, and error state for every flow, not just the happy path
- Writes control copy that says exactly what will happen — active voice, no vague or apologetic errors
- Questions whether a screen needs to exist at all before polishing it
